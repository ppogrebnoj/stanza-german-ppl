# Промт агенту: боевой прогон установки на новой машине

Скопировать целиком агенту, работающему на чистой Windows-машине (PowerShell 5.1+).

---

Ты ставишь этот проект с нуля и **меришь**. Полная инструкция — `УСТАНОВКА.md`: §1 человеку,
§2 агенту; ей и следуй, если что-то расходится с этим промтом.

1. `git clone https://github.com/ppogrebnoj/stanza-german-ppl.git C:\KI_WORK && cd C:\KI_WORK`
   (репозиторий приватный → п. 3).
2. Разведка: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\all.ps1 -CheckOnly -Json`.
   Читай `code` и `steps[]`.
3. Код **2** = нужен человек: спроси разрешение, потом попроси токен `github_pat_…`. Человек кладёт
   его в User-окружение сам: `[Environment]::SetEnvironmentVariable("GH_TOKEN","<токен>","User")`
   (в текущем процессе `setx` не виден). Токен не печатай и не сохраняй в файлах.
4. Установка (замер времени):
   `Measure-Command { powershell -NoProfile -ExecutionPolicy Bypass -File scripts\all.ps1 -Json -Log install.log }`
   Код 3 (шаг упал) — разберись и повтори ту же команду: шаги идемпотентны, готовые дают `SKIP`.
   Модели (~1.6 ГБ) качает Stanza у Stanford: `stanza-resources` + `huggingface.co`. В репозитории и
   в релизах архивов моделей нет — не ищи и не жди.
5. Приёмка, все команды из `.venv` (голый `python` в PATH — другая версия, даст FAIL):
   - `.venv\Scripts\python.exe scripts\doctor.py` → `FAIL 0`
   - `.venv\Scripts\python.exe правило\smoke_test.py` → `OK 11, FAIL 0, SKIP 2`
   - `.venv\Scripts\python.exe правило\smoke_test.py --full` → `OK 14, FAIL 0`, F1 **0.777** / **0.686**
   - `.venv\Scripts\python.exe правило\validator.py --set bench/sets/corpus52.jsonl` → `compliant 52`
   - `.venv\Scripts\python.exe правило\validator.py --set bench/sets/heldout_51.jsonl` → `compliant 45`
6. Замеры (цифры, не впечатления): время каждого шага из JSON/`install.log`, суммарное время
   установки, размер `.venv`, размер `%LOCALAPPDATA%\StanfordNLP`, свободное место на диске до/после,
   объём скачанного (если виден), код выхода `all.ps1` и все `SKIP`.
7. Отчёт: таблица «шаг → время/объём → факт против оценки §1.1 (`models ~1.6 ГБ`, `venv ~1 ГБ`,
   `10–20 мин`)» + список расхождений доков с реальностью (файл, строка, что написать) + итог приёмки.

Не делай: коммит/пуш; правки `requirements.txt`, `requirements.lock`, `bench/results/*`, кода и доков;
обновление зависимостей; чистку pip-кэша. Если нашёл расхождение — запиши в отчёт, не исправляй.
MCP не проверяй без клиента: конфиг делает человек из `MCP-stanza-german\mcp.json.example` (§1.3a);
после перезапуска клиента — `pipeline_info()`, `rule_self_test()`, `segment_german("Ich habe bei der
Firma gearbeitet.")` → `rule_registered: true`, `gate_passed: true`, 2 блока.
