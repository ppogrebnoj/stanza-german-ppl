# Установка на новой машине: что сломается и как это упростить

Отчёт-план. База — фактическая репетиция в чистом каталоге (этап 6) и проверки, сделанные
при подготовке: оба сценария (обычный и «чужой путь») пройдены, найденные баги уже починены.
Здесь — то, что ещё **не** покрыто, и план, как закрыть.

## Короткий вывод

1. **Уже устойчиво:** код, пути, модели, окружение и конфиг клиента переносятся скриптами;
   приёмка автоматизирована (`doctor`, `smoke_test --full`), CI проверяет чистый клон на каждой сборке.
2. **Осталось хрупким:** *всё, что до первого скрипта* — наличие Python/git/gh, права,
   сеть, версия Python. Сейчас на эти случаи есть только текст в `ПЕРЕНОС.md`, скрипты падают
   «по факту» (например, `python не найден`), а не заранее и не с альтернативой.
3. **Предлагаю** 6 доработок (~7.5 ч): единая команда установки, preflight «что есть на машине»,
   офлайн-набор, поддержка других MCP-клиентов, приёмка одной командой, ручной путь без PowerShell.

## Что реально нужно на целевой машине

| Компонент | Обязателен | Зачем | Без него |
|---|---|---|---|
| Windows 10/11 x64 | да | проект проверен здесь | Linux/macOS работают, но `setup.ps1` заменяется на 2 команды вручную |
| Python 3.11.x (x64) | да | правило, стенд, сервер | ничего не работает |
| Git | желательно | история, обновления, хук | можно копией папки, но без `pull` и без внешней копии |
| `gh` + авторизация | нет | скачать модели и репозиторий из private | модели — вручную из Releases, репозиторий — только при наличии доступа |
| Интернет до github.com и pypi.org | нет | зависимости (≈2.5 ГБ) и модели (315 МБ) | только офлайн-набор (см. §4) |
| Клиент MCP (LM Studio и др.) | нет | им пользуются в чате | сервер можно запустить вручную, правила работают из CLI |
| Права администратора | **не нужны** | все записи — в каталог проекта, `%LOCALAPPDATA%`, `%USERPROFILE%` | — |

Замеры на репетиции: клон 1.3 с · окружение ~2 мин (сеть рвалась, pip докачивал) ·
модели ~3 мин · venv 0.78 ГБ · модели 0.31 ГБ · архив в релизе 329 277 609 Б.

## 1. Матрица проблем и решений

Формат: **симптом → как обнаружить → решение** (✔ — уже работает, ⚠ — закрыто только текстом
в `ПЕРЕНОС.md`, ⛔ — не покрыто, нужен план).

### A. Не установлено нужное ПО

| Проблема | Симптом | Обнаружение | Решение |
|---|---|---|---|
| Нет Python | `setup.ps1`: «Python не найден» | сразу | `winget install -e --id Python.Python.3.11` или python.org; ✔ сообщение понятное, но нет подсказки установки |
| Python есть, но 3.13 (на машине только он) | `doctor`: WARN «проверен на 3.11»; всё работает | `doctor` | колёса `torch 2.14.0` есть под cp310–cp314, `numpy 2.4.6` — от cp311, `pyphen` — pure-python; установка проходит (проверено `pip --dry-run` на 3.13). ⚠ цифры F1 на 3.13 не перепроверялись |
| Python из Microsoft Store (заглушка) | `python` открывает Store | `setup.ps1` падает на `-c` | ставить python.org; ⛔ скрипт не отличает заглушку от реального Python |
| `py` launcher отсутствует, `python` в PATH не тот | ставится не та версия | ⚠ `setup.ps1` печатает WARNING | ⛔ нет параметра `-Python <путь>` |
| Нет git | `git` не найден | `doctor`: WARN «проект не под git» (если файлы принесли копией) | поставить Git for Windows; ⛔ в `setup.ps1` проверки нет |
| Нет `gh` | `unpack_models`: `gh` не найден | при скачивании моделей | скачать zip с релиза вручную + `--zip`; ⚠ текстовая инструкция, ⛔ скрипт не предлагает альтернативу сам |
| `gh` есть, но не авторизован | `gh: Not Found` / `auth` | `unpack_models` печатает короткую ошибку | `gh auth login`; ⛔ нет предварительной проверки |
| Нет клиента MCP | `install_mcp.py` создаёт `…\.lmstudio\mcp.json`, клиент его не читает | `doctor` этого не видит | ⛔ `install_mcp.py` знает только LM Studio; нет `--client` |

### B. Права доступа и политики

| Проблема | Симптом | Обнаружение | Решение |
|---|---|---|---|
| Нет прав администратора | — | — | **не требуется**: пишем только в каталог проекта, `%LOCALAPPDATA%\StanfordNLP`, `%USERPROFILE%\.lmstudio` |
| `ExecutionPolicy` запрещает скрипты | `setup.ps1` не запускается | при запуске | `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1` ✔ (так и написано в `ПЕРЕНОС.md`) |
| Политика GPO запрещает и Bypass | то же | при запуске | ⛔ нет ручного пути без PowerShell: нужен `scripts/setup.py` (чистый Python) |
| Антивирус/Defender замедляет или блокирует DLL torch | установка «висит», ложное срабатывание | долгая установка | добавить исключение для `.venv`; ⚠ не описано |
| Каталог проекта только для чтения (Program Files, сетевой шар) | ошибки записи venv/хука | `setup.ps1` падает на venv | ставить в профиль пользователя; ⛔ предварительной проверки записи нет |
| Запись в `%USERPROFILE%\.lmstudio` запрещена (управляемый профиль) | `install_mcp.py` падает | при записи | `--config <путь>` ✔ |

## 2. Что мешает сильнее всего (по итогам репетиции)

1. **Забытая зависимость** (`pyphen`) — fast-гейт зелёный, валидатор падал. Закрыто: пин + CI-job «полный прогон».
2. **Неочевидный интерпретатор** после `setup.ps1` (venv vs системный Python) — закрыто текстом.
3. **Модели решают всё**: без них не работают ни стенд, ни `smoke --full`, ни сервер; ошибка
   проявляется глубоко (`RuntimeError: Stanza pipeline…`), а не на входе.

## 3. План упрощения установки

Порядок — по соотношению «цена / покрытие рисков». Все пункты — идемпотентные, проверяемые в CI.

| № | Что | Закрывает | Файлы | Оценка | DoD |
|---|---|---|---|---|---|
| **U1** | `scripts/install.ps1` — **одна команда**: `-CheckOnly` / `-Offline` / `-NoModels` / `-Python <путь>` / `-Yes`; сам решает, что делать (deps → models → client → verify) и печатает итог PASS/FAIL | A, B, E | `scripts/install.ps1` (новый), `ПЕРЕНОС.md` | 1.5 ч | на чистой машине хватает одной команды; повторный запуск ничего не ломает |
| **U2** | `scripts/preflight.py` (встроить в `doctor`): наличие Python-версий, git, `gh` + авторизация, разрядность Python, свободное место, доступ на запись, `ExecutionPolicy`, прокси, доступность github/pypi, OneDrive в пути | A, B, C, D, E | `scripts/preflight.py`, `scripts/doctor.py` | 1 ч | на машине без Python/git/gh выводит список «чего не хватает» и что установить, до всяких падений |
| **U3** | `scripts/make_bundle.py` + `install.ps1 -Offline <каталог>`: git bundle, zip моделей, `pip download --platform win_amd64 --python-version 3.11 --only-binary=:all:`, `SHA256SUMS`, README | C (нет сети), C (закрыт pypi) | `scripts/make_bundle.py` (новый) | 2 ч | офлайн-набор (~3 ГБ) ставится на машине без сети; проверка сумм перед установкой |
| **U4** | `install_mcp.py --client lmstudio\|claude\|cursor\|custom --config <путь> --remove` | F, A (нет клиента) | `scripts/install_mcp.py` | 1 ч | для Claude Desktop и Cursor пишет корректный конфиг, сохраняет чужие серверы, `--remove` убирает запись |
| **U5** | `scripts/verify.py` — приёмка одной командой: `doctor` + `smoke_test` (fast, и `--full` если есть модели) + `validator --set corpus52` + `rule_self_test`; итог `PASS/FAIL` и код возврата | все | `scripts/verify.py` (новый) | 1 ч | в CI и на целевой машине одна команда говорит «готово/не готово» без чтения логов |
| **U6** | `setup.ps1 -Python <путь>` + `scripts/setup.py` (чистый Python, для GPO-заблокированного PowerShell) | A, B | `scripts/setup.ps1`, `scripts/setup.py` (новый) | 1 ч | установка проходит на машине, где `.ps1` не разрешены |

**Суммарно ≈7.5 ч.** Если время ограничено — делать **U1 + U2 + U5** (≈3.5 ч): они закрывают
установку «одной командой», объясняют, чего не хватает, и автоматизируют приёмку.
`U3` нужен только если целевая машина без интернета; `U4` — если клиент не LM Studio;
`U6` — если политики домена злые.

### Что специально НЕ делаем

* **Docker/образ** — на Windows-машине с MCP-клиентом это усложнение: stdio-сервер в контейнере
  требует проброса, а модели всё равно монтируются снаружи. Для Linux-сервера — отдельная тема.
* **Установка Python/git «за пользователя»** — не наша зона: `preflight` подскажет команду,
  но качать и ставить интерпретатор проект не должен.
* **Свой lock-резолвер/uv** — `requirements.txt` + `requirements.lock` уже покрывают
  воспроизводимость; менять инструмент смысла нет.

## 4. Сценарий «на машине нет интернета» (то, что войдёт в U3)

На машине **с** интернетом (или уже на этой):

```powershell
cd E:\KI_WORK
python scripts\make_bundle.py --out D:\ki-bundle      # ~3 ГБ
#   -> ki-bundle\repo.bundle            (полная история git)
#   -> ki-bundle\stanza-models-de-1.15.0.zip
#   -> ki-bundle\wheels\                (pip download под win_amd64 / cp311)
#   -> ki-bundle\SHA256SUMS
#   -> ki-bundle\README.txt             (что и как ставить офлайн)
```

На целевой машине:

```powershell
# 1. Python 3.11 x64 — единственное, что нужно принести отдельно (python-3.11.x-amd64.exe)
# 2. развернуть из набора
powershell -ExecutionPolicy Bypass -File D:\ki-bundle\install.ps1 -Offline D:\ki-bundle
#    внутри: git clone repo.bundle -> pip install --no-index --find-links wheels
#            -> распаковка моделей -> install_mcp -> verify
```

Пока этого нет — ручной офлайн-порядок (описан в `ПЕРЕНОС.md` частично):
`git bundle create repo.bundle --all` → `git clone repo.bundle C:\KI_WORK`;
`pip download -r requirements.txt -d wheels --platform win_amd64 --python-version 3.11 --only-binary=:all:`;
`unpack_models.py --zip`; `setup.ps1 -SkipDeps` + `pip install --no-index --find-links wheels -r requirements.txt`.

## 5. Что проверить на целевой машине **до** выезда

Мини-чек-лист (5 минут, экономит час переустановок):

```powershell
py -0                                  # есть ли 3.11 и какая версия по умолчанию
git --version                          # есть ли git
gh auth status                         # есть ли доступ к приватному репозиторию
python -c "import platform;print(platform.architecture())"   # 64-bit?
Get-PSDrive C | Select-Object @{n='FreeGB';e={[math]::Round($_.Free/1GB)}}
Get-ExecutionPolicy -List              # разрешены ли скрипты
Test-NetConnection github.com -Port 443; Test-NetConnection pypi.org -Port 443
```

Ожидаемо: Python 3.11 x64, git, `gh` авторизован, ≥4 ГБ свободно, скрипты разрешены
(или известен способ их запускать), оба хоста доступны.
