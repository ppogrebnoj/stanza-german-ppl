# УСТАНОВКА

Нарезка немецкого на блоки: правило + Stanza + валидатор + MCP-сервер. Эталон: **Python 3.15 x64**,
torch 2.15.0, numpy 2.5.5, stanza 1.15.0. Путь: Windows, PowerShell 5.1+.

## Быстрый старт

```powershell
git clone https://github.com/ppogrebnoj/stanza-german-ppl.git C:\KI_WORK && cd C:\KI_WORK
.\install.ps1 -Inventory     # сначала: что реально стоит на этой машине (§1.0)
.\install.ps1                # одна команда: живой прогресс → «ГОТОВО за N мин (код 0)»
```

**Зависимости ставятся ГЛОБАЛЬНО в системный Python 3.15 — это поведение по умолчанию.**
`.venv` — опция (`install.ps1 -Venv`), и она допустима: `doctor.py` считает отсутствие `.venv`
нормой («нет `.venv` — работа идёт на системном Python (допустимо)»). Подробности — §1.4.1.

Агент: `.\install.ps1 -CheckOnly -Json` → `.\install.ps1 -Json -ProgressJson -Log install.log`
(`install.ps1` ≡ `scripts\all.ps1`, старые ключи не ломаются).
Коды **0/2/3/4/5** и что делать по каждому — §2.2. Ключи: `-Inventory [-Json]` ·
`-CheckOnly` · `-DryRun` · `-Venv` (в `.venv`; по умолчанию — глобально) · `-Steps venv,deps,models,mcp,doctor` · `-Zip <архив>` ·
`-McpConfig <файл>` · `-Log install.log` · `-Json` · `-ProgressJson` · `-Yes` · `-InstallPython` ·
`-InstallGit` · `-InstallBuildTools` · `-Python <path>` · `-Help` (токены маскируются `github_pat_***`).

### 1.0 Проверь, что есть на самом деле — одна команда

```powershell
.\install.ps1 -Inventory         # компонент → версия/путь → статус → одна команда доустановки
.\install.ps1 -Inventory -Json    # то же машино, парсится ConvertFrom-Json
```

Только чтение (кроме `-Log`): не ставит, не правит реестр, не создаёт файлов. Без сети ≤ 3 с;
сетевой блок отдельный (HEAD, 5 с/хост, отключается `-NoNetwork`). Код: `0` — всё требуемое на месте,
`2` — чего-то не хватает, `4` — сломан запуск. Состав — 19 позиций:

| Группа | `name` |
|---|---|
| шелл / права | `shell`, `rights` |
| Python / git | `python`, `pip`, `venv`, `git`, `gh`, `GH_TOKEN` |
| winget / MSVC | `winget`, `msvc_vctools` |
| диск / сеть | `freespace_C`, `freespace_Z`, `project_disk`, `network` |
| MCP / проект | `mcp_client`, `project_venv`, `stanza_cache`, `hf_cache`, `pip_cache` |

Статусы: `OK` (есть, нужная версия/разрядность) · `MISSING` · `WRONG` (есть, но не то: 32-бит, 3.14,
ms-store) · `BASE_ONLY` (Build Tools без компилятора, §1.1) · `UNKNOWN` (проверить не смогли — `OK` по
умолчанию запрещено, печатается «как проверить руками») · вспомогательные — `PARTIAL`, `LOW`, `SLOW`,
`NOTE`, `ADMIN`, `USER`, `set`, `NOT_SET`, `NOT_REQUIRED` — по контексту. У `MISSING` /
`WRONG` / `BASE_ONLY` / `LOW` есть `fix`.

**«Нет в PATH» ≠ «не установлено».** Первым делом сбрасывается `PATH` = `Machine` + `User` (из-под
шелла агента/CI не видно `…\Microsoft\WindowsApps`), затем `py -0p` → реестр `PythonCore`
(HKCU / HKLM / WOW6432Node) → стандартные пути; winget — `Get-AppxPackage *DesktopAppInstaller*`;
MSVC — `vswhere -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64` и
папки `VC\Tools\MSVC\*`.

Зачем: статус компонента — только из замера (после отката VM «тут уже стоял Python 3.15» — неправда);
версии из docs и отчётов — гипотеза. Любой прогон начинается с инвентаризации; автоустановка
(`-Install*`) — только по явным флагам с `-Yes`.

### 1.0.1 Как читать вывод

Человек (без `-Json`) — строка обновляется на месте, шаг не «висит» молча:

```
[12/20] deps · pip torch 2.15.0 · 1.2/2.4 ГБ · 43% · ETA 6 мин
```

Формат: `[текущий/всего] шаг · подшаг · сделано/всего байт · % · ETA`; неизвестное — `…`, цифры не
выдумываются. Агент / CI (`-Json -ProgressJson`) — те же события потоком, NDJSON, одна JSON-строка на
событие, **до** итогового объекта:

```json
{"t":"2026-11-19T15:00:00Z","ev":"progress","step":"deps","sub":"pip torch","pct":43,"bytes":1288490188,"total":2576980377,"eta":360,"msg":"…"}
```

События `step_start` / `step_ok` / `step_skip` / `step_fail` (те же поля + `ev`) и `progress`; при
`-Json` без `-ProgressJson` в stdout только итоговый объект (обратная совместимость), события всегда
идут в `-Log` (UTF-8). Итог прогона — в корне проекта (в `.gitignore`): `install-report.json` (код,
время, объёмы, `free_space` C/Z до и после, `steps[]`) и `install-report.txt` человеку; в консоли —
`ГОТОВО за N мин (код 0) · подробно: install-report.txt`.

### 1.4.1 Глобально или в `.venv` — что выбрать

| | Глобально (по умолчанию) | `-Venv` |
|---|---|---|
| Куда ставятся пакеты | в системный Python 3.15 (`…\AppData\Local\Programs\Python\Python315`) | в `<проект>\.venv` |
| Кто ещё это видит | все проекты этой машины | только этот проект |
| Конфликт верностей | возможен (два проекта — два набора пинов) | нет |
| Воспроизводимость | зависит от состояния машины | `pip freeze` → `requirements.lock` |
| `doctor.py` | `WARN venv: нет .venv — работа идёт на системном Python (допустимо)` | `OK venv` |
| Статус приёмки | тот же, `FAIL 0` | тот же, `FAIL 0` |

Правила:

- **По умолчанию — глобально.** Это поведение `install.ps1`/`setup.ps1` без флагов.
- **`.venv` — опция.** `install.ps1 -Venv` (или `setup.ps1 -Venv [-VenvDir <путь>]`).
- Если `.venv` **уже существует**, он используется и без `-Venv` — чтобы не держать две копии
  torch по 2.4 ГБ. Вернуться к глобальной установке: удалить `.venv` и запустить снова.
- В `install-report.json` / `-Json` есть поле `install_mode`: `global` или `venv`; в префлайтe —
  `пакеты: есть (глобально)` / `пакеты: есть (.venv)`.
- `command` в `mcp.json` должен указывать на тот же интерпретатор: глобальный
  `…\Python315\python.exe` либо `.venv\Scripts\python.exe` (установщик печатает фрагмент уже
  с правильным путём).
