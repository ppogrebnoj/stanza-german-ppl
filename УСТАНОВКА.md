# Установка

Эталон: **Python 3.15 x64 · torch 2.15.0 · numpy 2.5.5 · stanza 1.15.0**. На нём: правила 52/52,
F1 **0.777** (corpus52) и **0.686** (heldout_51). Другие версии Python не поддерживаются: под них
нет колёс `numpy 2.5.5` (cp312+) и эталон на них не снимался.

```powershell
git clone https://github.com/ppogrebnoj/stanza-german-ppl.git C:\KI_WORK && cd C:\KI_WORK
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\all.ps1        # → «ГОТОВО», код 0
```

## 1. Человеку

### 1.1 Поставить на машину

| Компонент | Версия | Команда |
|---|---|---|
| Python x64 | **3.15** | `winget install --id Python.Python.3.15 -e --accept-package-agreements` |
| Git | ≥ 2.30 | `winget install --id Git.Git -e` |
| `gh` CLI | ≥ 2.40 | `winget install --id GitHub.cli -e` |

- Права администратора не нужны (установщики Python/Git могут попросить).
- Диск **≥ 7 ГБ** свободно. Модели **1.6 ГБ** (измерено 17.11.2026; архив релиза 329 МБ — это не
  размер установки), venv ~1 ГБ, кэш pip до 2.5 ГБ. ОЗУ ≥ 4 ГБ, время 8–15 мин.
- Сеть (443): `pypi.org`, `files.pythonhosted.org`, `github.com`, `api.github.com`,
  `codeload.github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`;
  прокси — `HTTPS_PROXY`/`HTTP_PROXY`.
- Не ставить: SSH-ключи, git-lfs, GPG, Node.js, Build Tools, Docker. Путь проекта любой
  (пробелы и кириллица проверены), кроме `Program Files` и папок OneDrive.
- Системный `python` может быть любой (на эталонной машине в PATH 3.12): скрипты ищут 3.15 через
  `py -0p`, команды дальше идут из `.venv`.

### 1.2 Доступ — два варианта

**а) Переменная окружения с токеном.** Fine-grained PAT: только `stanza-german-ppl`,
Contents: **Read-only**, срок 7–30 дней.

```powershell
[Environment]::SetEnvironmentVariable("GH_TOKEN", "ВСТАВИТЬ_ТОКЕН", "User")
```

В текущем окне значение не видно (`setx`-эффект) — `all.ps1` достаёт его из User-реестра сам.

**б) Скачать руками** (`gh` тогда не нужен): репозиторий (клон или ZIP) → в рабочую папку;
`stanza-models-de-1.15.0.zip` + `.sha256` со страницы Releases (тег `models-v1`) → **в корень
проекта**. `all.ps1` увидит архив и распакует его, в сеть за моделями не пойдёт.

Полный офлайн, если нужен и pip (собирается на машине с сетью):

```powershell
git bundle create D:\ki\repo.bundle --all
python scripts\pack_models.py --minimal --out D:\ki
python -m pip download -r requirements.txt -d D:\ki\wheels --platform win_amd64 --python-version 3.15 --only-binary=:all:
```

Целевая машина: `git clone D:\ki\repo.bundle C:\KI_WORK`, архив моделей в корень,
`all.ps1 -Steps venv`, `pip install --no-index --find-links D:\ki\wheels -r requirements.txt`,
`all.ps1 -Steps models,mcp,doctor`.

### 1.3 Что делает `all.ps1`

venv → пины `requirements.txt` → git-хук `pre-commit` → модели (локальный архив, иначе релиз
`models-v1` через `gh`) → проверка конфига MCP-клиента → `doctor.py`. Готовые шаги помечает `SKIP`,
перезапуск безопасен. Коды: **0** готово · **2** нужен человек · **3** шаг упал · **4** сломан запуск.
Ключи: `-CheckOnly -Json` · `-DryRun` · `-Steps venv,deps,models,mcp,doctor` · `-Zip <архив>` ·
`-Release <тег>` · `-Python <путь>` · `-MinFreeGB 7` · `-McpConfig <путь>` · `-McpKey <секция>` · `-Log <файл>`.

### 1.3a Конфиг MCP-клиента — создаёт человек

Файл `mcp.json` кладёт сам человек в каталог своего клиента, заменя пути на свои. Образец —
`MCP-stanza-german\mcp.json.example`:

```json
{
  "mcpServers": {
    "stanza-german": {
      "command": "C:\\KI_WORK\\.venv\\Scripts\\python.exe",
      "args": ["C:\\KI_WORK\\MCP-stanza-german\\server.py"],
      "env": { "RULE_ROOT": "C:\\KI_WORK\\правило", "PYTHONUTF8": "1" }
    }
  }
}
```

Куда положить: LM Studio `~\.lmstudio\mcp.json` · Claude Desktop `%APPDATA%\Claude\claude_desktop_config.json` ·
Cursor `~\.cursor\mcp.json` · Windsurf `~\.codeium\windsurf\mcp_config.json` · VS Code
`%APPDATA%\Code\User\mcp.json` (секция `servers`, добавь `"type": "stdio"`) · Gemini CLI
`~\.gemini\settings.json` · Codex `~\.codex\config.toml` (секция `[mcp_servers.stanza-german]`).
После правки — перезапуск клиента. `all.ps1` на шаге `mcp` печатает **готовый фрагмент с путями этой
машины** (в `-Json` он лежит в поле `mcp_snippet`) и проверяет, есть ли запись в конфиге
(`-McpConfig`, по умолчанию `~\.lmstudio\mcp.json`); если записи нет — код 2.

|---|---|---|

Модели — из релиза `models-v1` **этого** проекта: в `github.com/stanfordnlp/stanza` их нет, они
качаются с серверов Стэнфорда по тегу версии (набор 1.15.0 ⇄ stanza 1.15.0). Релизная копия даёт
то же + `.sha256` + офлайн + независимость от чужого сервера при установке.

### 1.7 Если что-то не так

| Симптом | Что делать |
|---|---|
| код 2 (префлайт) | нет Python 3.15 → `winget install --id Python.Python.3.15 -e`; нет токена → §1.2(а) или архив §1.2(б); мало места → `pip cache purge`; нет доступа к pypi.org → прокси/офлайн §1.2(б) |
| «Could not find a version that satisfies torch==2.15.0» | запущен не 3.15: `python -V` |
| `doctor` FAIL `stanza_de` | `.venv\Scripts\python.exe scripts\unpack_models.py --release models-v1 --check` |
| `unpack_models`: `gh: Not Found` | §1.2(а) или `--zip` локальный архив |
| «рядом нет .sha256» / `sha256 не совпал` | качать шаблоном `stanza-models-*.zip*` (так делает `--release`); битый архив удалить |
| `RuntimeError: Stanza pipeline не удалось загрузить` | задать `STANZA_RESOURCES_DIR` (путь печатает `unpack_models`) |
| `pipeline_info().notes`: «правило не подключено» | проверь `RULE_ROOT` в `mcp.json` (§1.3a) и перезапусти клиент |
| `ModuleNotFoundError: pyphen` | зависимости ставились не из `requirements.txt` → `setup.ps1` |
| обрыв сети у pip | повторить: pip докачивает, `unpack_models` ретраит сам (3 раза) |
| кракозябры в выводе | `chcp 65001` или Windows Terminal |

### 1.8 Обновления

Автообновления нет намеренно: эталон зафиксирован. Обновление только с проверкой колёс и приёмки.

```powershell
.venv\Scripts\python.exe scripts\pins.py            # под какие Python есть колёса у текущих пинов
.venv\Scripts\python.exe scripts\pins.py --latest   # что нового на PyPI
.venv\Scripts\python.exe scripts\pins.py --latest --write   # снимок bench/results/deps.json
```

Снимок `bench/results/deps.json` обновляет недельный job `pins` (одним коммитом в `master`), его
читает сервер: `pipeline_info().updates` = `{as_of, stale_days, python, outdated[], models_ok,
models_stanza}`. Только факты, без вердиктов; файла нет → `"available": false`.

`pins.py --latest` → правка `requirements.txt` (единственный файл пинов) → `pins.py` (покрытие
колёс обязано включать 3.15) → пересобрать `.venv` → §1.4 (те же 0.777/0.686) → `doctor` FAIL 0 →
`requirements.lock` (`pip freeze`) → CI зелёный. Еженедельный workflow `pins` показывает новые
версии; кандидат сейчас — **stanza 1.15.1** (патч, колёса не меняются). Мажорные (`mcp 2.x`)
требуют правки сервера. Единая проверка актуальности всех зависимостей (пакеты, модели, сервер)
и решение на её основе — план в `ПЛАН-ОБНОВЛЕНИЯ.md`.

## 2. Агенту

`all.ps1 -CheckOnly -Json` сначала, полный прогон после. Скрипт неинтерактивен — решает код выхода.

| Код | Значение | Действие |
|---|---|---|
| 0 | ГОТОВО | показать сводку `steps` |
| 2 | НУЖЕН ЧЕЛОВЕК | показать `hint`, не повторять и не угадывать |
| 3 | ШАГ УПАЛ (в check-only: «среда не готова») | один повтор шага, затем §1.7 |
| 4 | СЛОМАН ЗАПУСК | не чинить: сломаны файлы скриптов или ключи запуска |

- Токен: попросить человека, записать в **User**-переменную (`SetEnvironmentVariable(...,"User")`);
  `all.ps1` читает Process → User и сам делает `gh auth login --with-token` из stdin. Токен —
  нигде: не в файлах проекта, аргументах, логах, отчётах (маскируется `github_pat_***`).
- Идемпотентность: `SKIP` = уже сделано; модели не затираются без `--force`, `mcp.json` — с бэкапом
  `.json.bak-<дата>`. Повторный запуск — норма, не откат.
- MCP: конфиг `mcp.json` создаёт человек (§1.3a). `all.ps1` печатает готовый фрагмент этой машины
  (в `-Json` — поле `mcp_snippet`) и проверяет запись в `-McpConfig`; нет записи → код 2, не чини сам.
- Обновления: брать **только** из `pipeline_info().updates` (там `as_of`, `stale_days`,
  `outdated[{name,current,latest}]`, `models_ok`), ничего не искать в сети и не оценивать «безопасно».
  `as_of` старше ~10 дней = данные устарели: скажи «обновления не проверены». Правка пина = приёмка §1.4.
- Тяжёлую приёмку `all.ps1` **не** запускает: «ГОТОВО» ≠ «F1 сошёлся». Числа §1.4 сверять дословно
  (`OK 11`, `OK 14`, 0.777, 0.686, `compliant 52`, `compliant 45`); расхождение F1 → не та версия
  Python/пакетов → `pins.py`.
- Модели: локальный `stanza-models-de-*.zip` + `.sha256` в корне (быстро, без сети), иначе релиз
  `models-v1` через `gh`; в git архив не попадает, его приносит человек. Офлайн целиком: `-Steps venv`
  + `pip install --no-index --find-links <wheels>` + `-Steps models,mcp,doctor`.
- Официальный путь — Windows (PowerShell 5.1+); Linux/macOS скриптом-обёрткой не покрыты.
- CI (`smoke.yml`) проверяет: fast-гейт (Ubuntu+Windows), job `full` (Linux 3.15: requirements +
  модели релиза + `--check` + `smoke --full` + doctor), разбор `-DryRun` `setup.ps1`, job `all_ps1`
  (парсинг `all.ps1`, `-DryRun`, `-CheckOnly -Json`; краснеет на кодах 4 и 2). Реальную Windows-
  установку CI не прогоняет.
- Цифры: 1.6 ГБ моделей / 329 МБ архив — измерено 17.11.2026; числа приёмки — эталонная машина +
  job `full`; venv ~1 ГБ, 8–15 мин, кэш pip 2.5 ГБ — оценки. Живые значения этой машины —
  `all.ps1 -CheckOnly -Json`.
