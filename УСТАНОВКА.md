# Установка и перенос на другую машину

Эталон проекта: **Python 3.15 x64 · torch 2.15.0 · numpy 2.5.5**. Проверено: правила 52/52,
F1 **0.777** (corpus52) и **0.686** (heldout_51), `smoke_test --full` — OK 14 / FAIL 0.
Все остальные версии Python проектом не поддерживаются: на них нет колёс `numpy 2.5.5`
(колёса есть только с cp312) либо ломается воспроизводимость эталона.

## Что должно стоять на машине

| Компонент | Требование | Установка | Проверка |
|---|---|---|---|
| Python x64 | **3.15** | `winget install --id Python.Python.3.15 -e --accept-package-agreements` | `py -0` → `-V:3.15` |
| Git | ≥ 2.30 | `winget install --id Git.Git -e` | `git --version` |
| `gh` CLI | ≥ 2.40, авторизован | `winget install --id GitHub.cli -e` → `gh auth login` | `gh auth status` |

* Права администратора **не нужны**: всё пишется в каталог проекта, `%LOCALAPPDATA%\StanfordNLP`
  и `%USERPROFILE%\.lmstudio`. Установщики Python/Git — единственное, что может их попросить
  (при `--scope user` у Python прав не требуется).
* Свободно **≥ 4 ГБ** (venv ≈ 0.9 ГБ, кэш pip до 2.5 ГБ, модели 0.31 ГБ), ОЗУ ≥ 4 ГБ, время 8–15 мин.
* Сеть: `github.com`, `api.github.com`, `codeload.github.com`, `objects.githubusercontent.com`,
  `release-assets.githubusercontent.com`, `pypi.org`, `files.pythonhosted.org` (порт 443).
  Прокси — переменные `HTTPS_PROXY`/`HTTP_PROXY`, для git `git config --global http.proxy`.
* Ставить **не нужно**: SSH-ключи, git-lfs, GPG, Node.js, Visual Studio Build Tools, Docker.
* Путь проекта любой (пробелы и кириллица проверены), но не `Program Files` и не синхронизируемая папка OneDrive.
* `core.autocrlf=true` не мешает: в репозитории `.gitattributes` с `eol=lf` (сильнее `autocrlf`).

## Доступ к приватному репозиторию

**A. Токен (основной).** Создать fine-grained PAT: Repository access → только `stanza-german-ppl`,
Permissions → **Contents: Read-only**, срок 7–30 дней. Затем:

```powershell
"ВСТАВИТЬ_ТОКЕН" | gh auth login --with-token
gh auth setup-git
```

**B. Владелец выдаёт доступ по API:**

```powershell
gh api -X PUT repos/ppogrebnoj/stanza-german-ppl/collaborators/<github-username> -f permission=read
gh api repos/ppogrebnoj/stanza-german-ppl/collaborators --jq '.[].login'
```

**C. Без доступа.** Исходники архивом по API, модели — файлом с релиза:

```powershell
gh api repos/ppogrebnoj/stanza-german-ppl/zipball/master > src.zip
gh release download models-v1 -p "stanza-models-*.zip*" -D .
```

## Установка (5 шагов)

```powershell
git clone https://github.com/ppogrebnoj/stanza-german-ppl.git C:\KI_WORK
cd C:\KI_WORK

powershell -ExecutionPolicy Bypass -File scripts\setup.ps1                            # venv + пины + хук + doctor
.venv\Scripts\python.exe scripts\unpack_models.py --release models-v1 --check          # модели 315 МБ + 52/52
.venv\Scripts\python.exe scripts\install_mcp.py                                       # прописать сервер в клиенте
.venv\Scripts\python.exe scripts\doctor.py                                            # ожидается FAIL 0
```

После `setup.ps1` все дальнейшие команды — интерпретатором из `.venv` (или активировать
`.venv\Scripts\Activate.ps1`): `install_mcp.py` подставит его же в `mcp.json`.
`setup.ps1` сам находит Python 3.15 (через `py -0p`), проверяет версию **до** создания venv и при
отсутствии печатает команду winget. Параметры: `-Python <путь>`, `-SkipDeps`, `-UseLock`, `-DryRun`, `-VenvDir`.

Если `setup.ps1` заблокирован политикой PowerShell — те же шаги вручную:

```powershell
py -3.15 -m venv .venv
.venv\Scripts\python.exe -m pip install -U pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy правило\git-hooks\pre-commit .git\hooks\pre-commit     # хук: smoke-тест перед коммитом
```

**Без интернета** (на машине с сетью):

```powershell
git bundle create D:\ki-bundle\repo.bundle --all
python scripts\pack_models.py --minimal --out D:\ki-bundle
python -m pip download -r requirements.txt -d D:\ki-bundle\wheels --platform win_amd64 --python-version 3.15 --only-binary=:all:
```

На целевой машине: `git clone D:\ki-bundle\repo.bundle C:\KI_WORK`, затем
`setup.ps1 -SkipDeps`, `pip install --no-index --find-links wheels -r requirements.txt`,
`unpack_models.py --zip ...`, `install_mcp.py`. Модели можно принести и просто файлом с релиза.

## Если что-то не так

| Симптом | Причина / что делать |
|---|---|
| `setup.ps1`: «нет поддерживаемого Python (нужен 3.15)» | поставить 3.15: `winget install --id Python.Python.3.15 -e` |
| `pip`: «Could not find a version that satisfies torch==2.15.0» | запущен не тот интерпретатор — проверьте `python -V`; нужен 3.15 |
| `doctor`: FAIL `stanza_de` | не распакованы модели → `unpack_models.py --release models-v1 --check` |
| `unpack_models`: `gh: Not Found` | `gh` не авторизован → `gh auth login`; либо скачать zip на странице Releases и `--zip` |
| `unpack_models`: «рядом нет .sha256» | скачан только zip; скачивайте шаблоном `stanza-models-*.zip*` (так делает `--release`) |
| `RuntimeError: Stanza pipeline не удалось загрузить` | модели в нестандартном каталоге → задать `STANZA_RESOURCES_DIR` (его печатает `unpack_models`) |
| `pipeline_info().notes`: «правило не подключено» | `python scripts\install_mcp.py` (перезапишет `env.RULE_ROOT`) |
| `ModuleNotFoundError: pyphen` | зависимости ставились не из `requirements.txt` → `setup.ps1` |
| `pip`: `ConnectionReset` / обрыв | повторить: pip докачивает, `unpack_models` ретраит сам |
| `sha256 не совпал` | битый архив → удалить zip, скачать заново |
| `setup.ps1` не запускается | `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1` |
| кракозябры в выводе | скрипты печатают UTF-8: `chcp 65001` или Windows Terminal |

## Обновление зависимостей

Правило: **никаких обновлений без проверки колёс и прогона приёмки** — эталон зафиксирован.

```powershell
python scripts\pins.py            # матрица: под какие версии Python есть колёса у текущих пинов
python scripts\pins.py --latest   # что нового на PyPI
```

Порядок:

1. `pins.py --latest` → увидели новую версию.
2. Правка `requirements.txt` (единственный файл пинов).
3. `pins.py` → покрытие колёс должно включать **3.15** (иначе обновление ломает установку).
4. Пересоздать `.venv` (или `pip install -r requirements.txt --upgrade`) и прогнать приёмку:
   `smoke_test --full` должен дать те же **0.777 / 0.686**.
5. Прогнать `doctor.py` → FAIL 0.
6. Пересобрать `requirements.lock`: `python -m pip freeze`.
7. CI (job «полный прогон 3.15») должен быть зелёным; еженедельный workflow `pins` напомнит об обновлениях.

**Ближайший кандидат на обновление — `stanza 1.15.1`** (патч к 1.15.0): колёса не меняются, риск низкий;
проверять всё равно по шагам выше (после правки — `pins.py`, приёмка, lock). Мажорные обновления
(`mcp 2.x`) требуют отдельного прогона и правки кода сервера.
