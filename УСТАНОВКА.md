# Установка

Эталон: **Python 3.15 x64 · torch 2.15.0 · numpy 2.5.5 · stanza 1.15.0**. На нём: правила 52/52,
F1 **0.777** (corpus52) и **0.686** (heldout_51). Другие версии Python не поддерживаются: под них
нет колёс `numpy 2.5.5` (cp312+) и эталон на них не снимался.

```powershell
git clone https://github.com/ppogrebnoj/stanza-german-ppl.git C:\KI_WORK && cd C:\KI_WORK
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\all.ps1        # → «ГОТОВО», код 0
```

## 1. Человеку

### 1.1 Поставить на машину

| Компонент | Версия | Команда |
|---|---|---|
| Python x64 | **3.15** | `winget install --id Python.Python.3.15 -e --accept-package-agreements` |
| Git | ≥ 2.30 | `winget install --id Git.Git -e` |
| `gh` CLI | ≥ 2.40 | `winget install --id GitHub.cli -e` |

Ставить обязательно — Python и Git. `gh` нужен **только тем, кто правит репозиторий** (push):
на чтение (клон и установка) он не нужен, репозиторий публичный, модели качает Stanford (§1.2).

- Права администратора не нужны (установщики Python/Git могут попросить).
- Диск **≥ 7 ГБ** свободно. Модели de **~1.6 ГБ** на диске и столько же качаются с Hugging Face
  (измерено 17.11.2026), venv ~1 ГБ, кэш pip до 2.5 ГБ. ОЗУ ≥ 4 ГБ, время 10–20 мин (модели долгие).
- Сеть (443): `pypi.org`, `files.pythonhosted.org`, `github.com`, `api.github.com`,
  `raw.githubusercontent.com` (список ресурсов `stanza-resources`), `huggingface.co` и его CDN
  `cdn-lfs.huggingface.co` (файлы моделей); прокси — `HTTPS_PROXY`/`HTTP_PROXY`.
- Не ставить: SSH-ключи, git-lfs, GPG, Node.js, Build Tools, Docker. Путь проекта любой
  (пробелы и кириллица проверены), кроме `Program Files` и папок OneDrive.
- Системный `python` может быть любой (на эталонной машине в PATH 3.12): скрипты ищут 3.15 через
  `py -0p`, команды дальше идут из `.venv`.

### 1.2 Доступ и клон

Репозиторий **публичный**: для клона и установки токен, `gh` и SSH-ключи не нужны — чтение по https:

```powershell
git clone https://github.com/ppogrebnoj/stanza-german-ppl.git C:\KI_WORK
```

Модели скачивает сам Stanza с официального источника Stanford (§1.3): держать их в этом репозитории
смысла нет.

**Права на запись** (коммиты, push) — отдельный доступ, он нужен не всем и установке не мешает:

```powershell
winget install --id GitHub.cli -e
gh auth login --hostname github.com --git-protocol https --web   # браузер, токен в keyring
gh auth setup-git                                                 # git получит credential helper
```

Вместо `gh` подходит fine-grained PAT: только `stanza-german-ppl`, Contents **Read and write**,
срок 7–30 дней, в **User**-переменной:
`[Environment]::SetEnvironmentVariable("GH_TOKEN", "<токен>", "User")` (в текущем окне значение не
видно — `setx`-эффект, окно перезапустить). Токен не попадает в файлы проекта, аргументы, логи и
отчёты; `all.ps1` маскирует `github_pat_***`.

Полный офлайн, если он нужен (готовится на машине с сетью; архив моделей — со своего кэша):

```powershell
git bundle create D:\ki\repo.bundle --all
python scripts\pack_models.py --minimal --out D:\ki          # архив из кэша Stanza + .sha256
python -m pip download -r requirements.txt -d D:\ki\wheels --platform win_amd64 --python-version 3.15 --only-binary=:all:
```

Целевая машина: `git clone D:\ki\repo.bundle C:\KI_WORK`, архив моделей в корень,
`all.ps1 -Steps venv`, `pip install --no-index --find-links D:\ki\wheels -r requirements.txt`,
`all.ps1 -Steps models,mcp,doctor` — шаг `models` увидит архив, распакует его
`unpack_models.py --zip` и в сеть не пойдёт.

### 1.3 Что делает `all.ps1`

venv → пины `requirements.txt` → git-хук `pre-commit` → модели (локальный архив в корне, иначе
официальная загрузка Stanford: `stanza.download('de')` — список ресурсов со `stanza-resources` и
файлы с `huggingface.co`) → проверка конфига MCP-клиента → `doctor.py`. Готовые шаги помечает `SKIP`,
перезапуск безопасен. Коды: **0** готово · **2** нужен человек · **3** шаг упал · **4** сломан запуск.
Ключи: `-CheckOnly -Json` · `-DryRun` · `-Steps venv,deps,models,mcp,doctor` · `-Zip <архив>` ·
`-Python <путь>` · `-MinFreeGB 7` · `-McpConfig <путь>` · `-McpKey <секция>` · `-Log <файл>`.

### 1.3a Конфиг MCP-клиента — создаёт человек

Файл `mcp.json` кладёт сам человек в каталог своего клиента, заменя пути на свои. Образец —
`MCP-stanza-german\mcp.json.example`:

```json
{
  "mcpServers": {
    "stanza-german": {
      "command": "C:\\KI_WORK\\.venv\\Scripts\\python.exe",
      "args": ["C:\\KI_WORK\\MCP-stanza-german\\server.py"],
      "env": { "RULE_ROOT": "C:\\KI_WORK\\правило", "PYTHONUTF8": "1" }
    }
  }
}
```

Куда положить: LM Studio `~\.lmstudio\mcp.json` · pi `~\.pi\agent\mcp.json` · Claude Desktop
`%APPDATA%\Claude\claude_desktop_config.json` ·
Cursor `~\.cursor\mcp.json` · Windsurf `~\.codeium\windsurf\mcp_config.json` · VS Code
`%APPDATA%\Code\User\mcp.json` (секция `servers`, добавь `"type": "stdio"`) · Gemini CLI
`~\.gemini\settings.json` · Codex `~\.codex\config.toml` (секция `[mcp_servers.stanza-german]`).
После правки — перезапуск клиента. `all.ps1` на шаге `mcp` печатает **готовый фрагмент с путями этой
машины** (в `-Json` он лежит в поле `mcp_snippet`) и проверяет, есть ли запись в конфиге
(`-McpConfig`, по умолчанию `~\.lmstudio\mcp.json`); если записи нет — код 2.

Шаг ловит и типовые поломки самой записи: `"enabled": false` (клиент такой сервер не запускает) и
`command` на путь, которого на машине нет, — оба дают код 2 с подсказкой. Если установка ещё не
делалась (`.venv` отсутствует), отсутствующий `command` — шаг `NOTE`, не ошибка. `command` обязан
показывать на интерпретатор **с пакетами**: `.venv\Scripts\python.exe`; голый `python` в PATH —
обычно другая версия без `mcp`/`stanza`, сервер на ней не поднимется.

### 1.7 Если что-то не так

| Симптом | Что делать |
|---|---|
| `push`: 403 / `permission denied` / 401 | прав на запись нет (публичный репозиторий читается без токена, пишется — нет): `gh auth login` + `gh auth setup-git` или PAT с Contents: **Read and write** (§1.2); окно после `SetEnvironmentVariable` перезапустить |
| код 2 (префлайт) | нет Python 3.15 → `winget install --id Python.Python.3.15 -e`; мало места → `pip cache purge`; нет доступа к pypi.org → прокси/офлайн §1.2; в конфиге MCP нет записи `stanza-german` → §1.3a |
| «Could not find a version that satisfies torch==2.15.0» | запущен не 3.15: `python -V` |
| `doctor` FAIL `stanza_de` | `.venv\Scripts\python.exe -c "import stanza; stanza.download('de', verbose=False)"`, затем приёмка §1.4 |
| `stanza.download` падает или висит | доступны ли `huggingface.co`, `cdn-lfs.huggingface.co`, `raw.githubusercontent.com` (443); повторить команду — докачиваются отсутствующие файлы |
| «рядом нет .sha256» / `sha256 не совпал` (офлайн-архив) | архив делает человек `pack_models.py` (он пишет `.sha256`); битый пересобрать |
| `RuntimeError: Stanza pipeline не удалось загрузить` | задать `STANZA_RESOURCES_DIR` (путь печатает `unpack_models`) |
| `pipeline_info().notes`: «правило не подключено» | проверь `RULE_ROOT` в `mcp.json` (§1.3a) и перезапусти клиент |
| MCP-клиент не запускает сервер, список инструментов пуст | `all.ps1 -CheckOnly -Steps mcp -McpConfig <файл клиента> -Json` → код 2 и подсказка: нет записи / `"enabled": false` / `command` не найден. Голый `python` в PATH = 3.12 без `mcp` → нужен `.venv\Scripts\python.exe` (он же в `mcp_snippet`); после правки — перезапуск клиента |
| в логе сервера: `Pretrained file ... conll17.pt does not exist` | кэш был указан во временную папку (`STANZA_RESOURCES_DIR=%TEMP%\stanza-min` — её чистят): убери переменную, стандарт — `%LOCALAPPDATA%\StanfordNLP\stanza\Cache\1.15.0\resources`; сервер в сеть не ходит (`download_method=None`) |
| `ModuleNotFoundError: pyphen` | зависимости ставились не из `requirements.txt` → `setup.ps1` |
| обрыв сети у pip | повторить: pip докачивает с места, `stanza.download` докачивает отсутствующие файлы |
| кракозябры в выводе | `chcp 65001` или Windows Terminal |

### 1.8 Обновления

Автообновления нет намеренно: эталон зафиксирован. Обновление только с проверкой колёс и приёмки.

```powershell
.venv\Scripts\python.exe scripts\pins.py            # под какие Python есть колёса у текущих пинов
.venv\Scripts\python.exe scripts\pins.py --latest   # что нового на PyPI
.venv\Scripts\python.exe scripts\pins.py --latest --write   # снимок bench/results/deps.json
```

Снимок `bench/results/deps.json` обновляет недельный job `pins` (одним коммитом в `master`), его
читает сервер: `pipeline_info().updates` = `{as_of, stale_days, python, outdated[], models_ok,
models_stanza}`. Только факты, без вердиктов; файла нет → `"available": false`.

`pins.py --latest` → правка `requirements.txt` (единственный файл пинов) → `pins.py` (покрытие
колёс обязано включать 3.15) → пересобрать `.venv` → §1.4 (те же 0.777/0.686) → `doctor` FAIL 0 →
`requirements.lock` (`pip freeze`) → CI зелёный. Еженедельный workflow `pins` показывает новые
версии; кандидат сейчас — **stanza 1.15.1** (патч, колёса не меняются). Мажорные (`mcp 2.x`)
требуют правки сервера. Снимок актуальности (пакеты + модели + версия stanza) пишется в
`bench/results/deps.json`, агент читает его через `pipeline_info().updates` (§1.8).

## 2. Агенту

`all.ps1 -CheckOnly -Json` сначала, полный прогон после. Скрипт неинтерактивен — решает код выхода.

| Код | Значение | Действие |
|---|---|---|
| 0 | ГОТОВО | показать сводку `steps` |
| 2 | НУЖЕН ЧЕЛОВЕК | показать `hint`, не повторять и не угадывать |
| 3 | ШАГ УПАЛ (в check-only: «среда не готова») | один повтор шага, затем §1.7 |
| 4 | СЛОМАН ЗАПУСК | не чинить: сломаны файлы скриптов или ключи запуска |

- Доступ: **чтение** (клон, установка) — без токена, репозиторий публичный (§1.2). **Запись**
  (push) — доступ человека: `gh auth login` + `gh auth setup-git` или PAT (Contents: Read and write)
  в **User**-переменной; `all.ps1` читает Process → User, `gh` в префлейте — шаг `NOTE`, не блокер.
  Нет авторизации на запись — коммить локально и скажи человеку. Токен нигде не светится: не в
  файлах проекта, аргументах, логах, отчётах (маскируется `github_pat_***`).
- Идемпотентность: `SKIP` = уже сделано; модели не затираются без `--force`, `mcp.json` — с бэкапом
  `.json.bak-<дата>`. Повторный запуск — норма, не откат.
- MCP: конфиг `mcp.json` создаёт человек (§1.3a). `all.ps1` печатает готовый фрагмент этой машины
  (в `-Json` — поле `mcp_snippet`) и проверяет запись в `-McpConfig`; нет записи → код 2, не чини сам.
  Код 2 дают и поломки записи: `"enabled": false` (клиент не стартует) и `command` на несуществующий
  путь. Файл клиента — не репозиторий: правки только с разрешения человека, path бери из `mcp_snippet`.
- Обновления: брать **только** из `pipeline_info().updates` (там `as_of`, `stale_days`,
  `outdated[{name,current,latest}]`, `models_ok`), ничего не искать в сети и не оценивать «безопасно».
  `as_of` старше ~10 дней = данные устарели: скажи «обновления не проверены». Правка пина = приёмка §1.4.
- Тяжёлую приёмку `all.ps1` **не** запускает: «ГОТОВО» ≠ «F1 сошёлся». Числа §1.4 сверять дословно
  (`OK 11`, `OK 14`, 0.777, 0.686, `compliant 52`, `compliant 45`); расхождение F1 → не та версия
  Python/пакетов → `pins.py`.
- Модели: локальный `stanza-models-de-*.zip` + `.sha256` в корне (офлайн, секунды), иначе
  официальная загрузка `stanza.download('de')` (Stanford: `stanza-resources` + `huggingface.co`).
  В репозитории и в релизах архивов моделей нет — не ищи. Офлайн целиком: `-Steps venv` +
  `pip install --no-index --find-links <wheels>` + `-Steps models,mcp,doctor`.
- Официальный путь — Windows (PowerShell 5.1+); Linux/macOS скриптом-обёрткой не покрыты.
- CI (`smoke.yml`) проверяет: fast-гейт (Ubuntu+Windows), job `full` (Linux 3.15: requirements +
  модели от Stanford через `stanza.download` + правило на 52 + `smoke --full` + doctor), разбор
  `-DryRun` `setup.ps1`, job `all_ps1` (парсинг `all.ps1`, `-DryRun`, шаг `mcp` на образце конфига,
  `-CheckOnly -Json`; краснеет на коде 4). Реальную Windows-установку CI не прогоняет.
- Цифры: модели ~1.6 ГБ с HF и столько же на диске — измерено 17.11.2026; числа приёмки — эталонная машина +
  job `full`; venv ~1 ГБ, 10–20 мин, кэш pip 2.5 ГБ — оценки. Живые значения этой машины —
  `all.ps1 -CheckOnly -Json`.
- Боевой прогон на новой машине — промт собирается из этого файла: §2 (порядок и коды) + §1.4
  (приёмка). Агент обязан мерить: время каждого шага из `-Json`/`-Log`, размер `.venv`, размер
  `%LOCALAPPDATA%\StanfordNLP`, диск до/после, все `SKIP` — и докладывать расхождения §1.1 с
  реальностью. Правок не делать: ни коммитов, ни пинов, ни чистки pip-кэша.
