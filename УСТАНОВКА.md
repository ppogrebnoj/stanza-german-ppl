# УСТАНОВКА

Нарезка немецкого на блоки: правило + Stanza + валидатор + MCP-сервер. Эталон: **Python 3.15 x64**,
torch 2.15.0, numpy 2.5.5, stanza 1.15.0. Путь: Windows, PowerShell 5.1+.

```powershell
git clone https://github.com/ppogrebnoj/stanza-german-ppl.git C:\KI_WORK && cd C:\KI_WORK
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\all.ps1     # → «ГОТОВО» (код 0)
```

Коды: **0** готово · **2** нужен человек (читать `hint`) · **3** шаг упал (повторить тот же шаг) ·
**4** сломан запуск. Ключи: `-CheckOnly -Json` · `-DryRun` · `-Steps venv,deps,models,mcp,doctor` ·
`-Zip <архив>` · `-McpConfig <файл>` · `-Log install.log` (токены маскируются `github_pat_***`).

## 1. Человек

### 1.1 Python 3.15 x64, Git и MSVC Build Tools

```powershell
winget install --id Python.Python.3.15 -e --accept-package-agreements
winget install --id Git.Git -e
py -0p          # обязан показать 3.15.x 64bit; после установки — новое окно PowerShell (PATH)
```

**MS VC++ Build Tools — обязательны на Windows** (правят §1.1 «права админа не нужны»: они нужны
для Build Tools). У `PyYAML 6.0.3` (его тянет `stanza` → `huggingface-hub`, `pyyaml>=5.1`) нет ни
одного колеса `cp315` — на всех релизах максимум `cp313`/`cp314`, — значит на 3.15 pip берёт sdist и
собирает C-расширение `_yaml`. Понизить pyyaml нельзя (`cp313`-колесо под `cp315` не ставится),
обновить нечем: 6.0.3 = latest. В коде проекта `yaml` не импортируется, он нужен только
`huggingface_hub`. Base-пакет Build Tools (`Microsoft.VisualStudio.BuildTools`, ~110 МБ) даёт
MSBuild, но **не** компилятор — нужен workload `VCTools`:

```powershell
winget install -e --id Microsoft.VisualStudio.BuildTools --override "--add Microsoft.VisualStudio.Workload.VCTools --includeRecommended --quiet --wait --norestart"
# без winget (alias aka.ms/vs/18/release/… не существует — редиректит на bing):
curl.exe -L -o $env:TEMP\vs_buildtools.exe https://aka.ms/vs/18/stable/vs_buildtools.exe
#   start /wait $env:TEMP\vs_buildtools.exe --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended --quiet --wait --norestart
# если инстанс уже стоит и winget говорит «No available upgrade found» — модифицировать инсталлятором:
#   & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vs_installer.exe" modify --installPath "${env:ProgramFiles(x86)}\Microsoft Visual Studio\18\BuildTools" --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended --quiet --wait --norestart
# проверка компилятора (пусто = компилятора нет, pip упадёт на pyyaml):
& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -all -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
```

Без `winget` (нет Магазина) — те же компоненты официальными установщиками, права админа не нужны:

```powershell
curl.exe -L -o $env:TEMP\py315.exe https://www.python.org/ftp/python/3.15.2/python-3.15.2-amd64.exe
start /wait $env:TEMP\py315.exe /quiet InstallAllUsers=0 PrependPath=1 Include_launcher=1 Include_test=0
curl.exe -L -o $env:TEMP\git.exe https://github.com/git-for-windows/git/releases/download/v2.56.1.windows.1/Git-2.56.1-64-bit.exe
start /wait $env:TEMP\git.exe /VERYSILENT /NORESTART
```

`winget` по желанию (проекту не нужен), Windows PowerShell + админ, Win10 1809+:
`Install-PackageProvider -Name NuGet -Force` → `Install-Module Microsoft.WinGet.Client -Force
-Repository PSGallery` → `Repair-WinGetPackageManager -AllUsers`.

- Диск **≥ 7 ГБ** + Build Tools с `VCTools` **ещё 3–4 ГБ** (итого ≥ 11 ГБ); модели ~1.6 ГБ +
  venv 874 МБ + кэш pip до 2.5. ОЗУ ≥ 4 ГБ. Время: 10–20 мин (оценка без Build Tools),
  + 10–30 мин на `VCTools` (скачка ~2 ГБ, ставится молча, прогресса не показывает).
- Сеть 443: `pypi.org`, `files.pythonhosted.org`, `github.com`, `api.github.com`,
  `raw.githubusercontent.com`, `huggingface.co`, `cdn-lfs.huggingface.co`; прокси `HTTPS_PROXY`.
- **Не** ставить: git-lfs, Node.js, Docker, SSH-ключи. (Build Tools — наоборот, **обязательны**,
  см. выше: без `VCTools` шаг `deps` падает на pyyaml.) Системный `python` любой
  (скрипты ищут 3.15 через `py -0p`); путь проекта любой, кроме `Program Files` и OneDrive.
- **Даунгрейд запрещён**: Python строго 3.15 (колёса torch 2.15.0 = cp311..cp315, numpy 2.5.5 =
  cp312..cp315, цифры приёмки сняты на 3.15). Модели качает Stanford (адреса — в `resources.json`
  кэша); в git и релизах их архивов нет.

### 1.2 Доступ

Чтение — без токена, репозиторий публичный (клон выше). Запись (кому нужны пуши), два варианта:

```powershell
winget install --id GitHub.cli -e    # без winget: curl.exe -L -o gh.msi https://github.com/cli/cli/releases/download/v2.104.0/gh_2.104.0_windows_amd64.msi ; msiexec /i gh.msi /qn
gh auth login --hostname github.com --git-protocol https --web   # браузер, токен в keyring
gh auth setup-git                                                # git получит credential helper
# или fine-grained PAT (только stanza-german-ppl, Contents: Read and write, 7–30 дней):
[Environment]::SetEnvironmentVariable("GH_TOKEN", "<токен>", "User")   # окно перезапустить (setx-эффект)
```

Проверка: `gh auth status` · `git ls-remote …stanza-german-ppl.git` · `git push --dry-run`. Токен не
попадает в файлы проекта, аргументы, логи, отчёты; `all.ps1` читает `GH_TOKEN`/`GITHUB_TOKEN`
(Process → User) и сам делает `gh auth login --with-token` из stdin.

### 1.7 Обновления

`scripts\pins.py --latest --write bench/results/deps.json` — снимок, его читает MCP
(`pipeline_info().updates`, свежесть по `as_of`); workflow `pins` обновляет файл в git еженедельно.
Правка пина: `requirements.txt` → `pins.py` (колёса обязаны включать 3.15) → пересборка `.venv` →
§1.4 (те же 0.777/0.686) → `doctor` FAIL 0 → `requirements.lock` (`pip freeze`) → CI. Кандидат:
**stanza 1.15.1** (патч); мажорные (`mcp 2.x`) требуют правки сервера.

## 2. Агент

### 2.1 Порядок

`all.ps1 -CheckOnly -Json` → разобрать `code`/`steps[]` → `all.ps1 -Json -Log install.log` (шаги
идемпотентны, готовые `SKIP`) → приёмка §1.4 дословно → `scripts\mcp_probe.py` из `.venv` → отчёт:
время шагов из JSON, размер `.venv` и кэша моделей, диск до/после, все `SKIP`, коды, замеры против
оценок §1.1. Шаг `deps` на Windows требует MSVC (`VCTools`, §1.1): без него код 3 на pyyaml —
это не «повторить», а блокер уровня человека. Обновления — только по указанию человека.

### 2.2 Коды

| Код | Значение | Действие |
|---|---|---|
| 0 | ГОТОВО | показать сводку `steps` |
| 2 | НУЖЕН ЧЕЛОВЕК | показать `hint` дословно, спросить, не угадывать |
| 3 | ШАГ УПАЛ (в `-CheckOnly` = «среды нет», до установки норма) | один повтор шага, затем §1.6 |
| 4 | СЛОМАН ЗАПУСК | не чинить: сломаны файлы скриптов или ключи запуска |

### 2.3 Нельзя

Даунгрейд Python и пакетов (только 3.15, пины только из `requirements.txt`); обновления без явного
указания; поиск архивов моделей в git и релизах; правка конфига MCP-клиента (печатать
`mcp_snippet`, файл правит человек); токен — не печатать, не в файлы/логи/коммиты; числа правила
(`ПРАВИЛО.md`, `правило/config.json`) и `bench/results/*` — без указания; чистка pip-кэша;
`requirements.lock` руками.

### 2.4 Что видно из скрипта

`preflight NOTE` — справка (нет `gh` → для установки не нужен, для push §1.2); `mcp NOTE/BLOCK` →
код 2: нет записи, `enabled: false`, `command` в несуществующий путь; `SKIP` — уже сделано. Тяжёлую
приёмку `all.ps1` не запускает: «ГОТОВО» ≠ «F1 сошёлся» → числа §1.4 сверять дословно, расхождение →
не та версия Python/пакеты → `pins.py`. Обновления — только из `pipeline_info().updates` (`as_of`
старше ~10 дней = «обновления не проверены»).

### 2.5 CI и эталон

`smoke.yml`: fast-гейт Ubuntu+Windows; job `full` (Linux 3.15: requirements + модели от Stanford +
правило 52 + `smoke --full` + doctor + `mcp_probe`); разбор `setup.ps1 -DryRun`; job `all_ps1`
(парсинг, `-DryRun`, шаг `mcp` на образце, `-CheckOnly -Json`; краснеет на коде 4). Реальную
Windows-установку CI не делает, поэтому падение `deps` на pyyaml (нет cp315-колёс → сборка из sdist,
§1.1) в CI не виден: чистая Windows-машина без `VCTools` его воспроизводит, а Linux-прогон — нет.
Эталон этой машины (17.11.2026): `doctor OK 18`, `smoke --full OK 14`,
F1 0.777 / 0.686, `compliant 52` / `45`, venv 874 МБ, кэш моделей 1.59 ГБ. Боевой прогон на новой
машине = §2.1 + §1.4 + замеры; промт собирается из этих разделов.
