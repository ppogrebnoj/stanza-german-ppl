# Перенос проекта на другую машину

Проверено на чистом клоне: 5 шагов, ~10 минут (из них основное — скачать зависимости).
Всё машинно-зависимое (пути, окружение, конфиг клиента) генерируется скриптами,
поэтому ни один файл править руками не нужно.

## Что где живёт

| Что | Где | Объём | Переносится |
|---|---|---|---|
| Код, правило, разметка, наборы, цифры | GitHub `ppogrebnoj/stanza-german-ppl` (private) | ~2 МБ | `git clone` |
| Модели Stanza (`de`) | GitHub Releases, тег `models-v1` | **315 МБ** (329 277 609 Б) | `scripts/unpack_models.py` |
| Python-зависимости | `requirements.txt` (4 пина) / `requirements.lock` (49) | ~2.5 ГБ в venv | `scripts/setup.ps1` |
| Конфиг MCP-клиента | `%USERPROFILE%\.lmstudio\mcp.json` | 1 КБ | `scripts/install_mcp.py` |
| Git-хук pre-commit | `.git/hooks/pre-commit` | 1 КБ | `scripts/setup.ps1` |
| Кэш разборов стенда | `bench/cache/` (в git не хранится) | 280 КБ | `python bench/pcache.py` (≈1 мин) |

Итого на диске: ~3 ГБ (venv с torch ≈2.5 ГБ + модели 0.31 ГБ + проект).

## Требования

* Windows 10/11 (Linux/macOS — те же команды, кроме `setup.ps1`: см. ниже).
* Python **3.11.x** в PATH (или `py -3.11`).
* Git.
* GitHub CLI `gh`, авторизованный (`gh auth status`) — им качается ассет моделей из приватного релиза.
  Без `gh`: скачайте `stanza-models-de-1.15.0.zip` вручную со страницы Releases и передайте файлом.
* Свободные ~4 ГБ на диске.

## Развернуть на новой машине

Путь проекта — любой (`C:\KI_WORK`, `D:\work\ki` и т.п.): пути считаются от расположения файлов.

```powershell
# 1. код (полная история, ветка master)
git clone https://github.com/ppogrebnoj/stanza-german-ppl.git C:\KI_WORK
cd C:\KI_WORK

# 2. окружение: venv + пины + git-хук + preflight
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1

# 3. модели Stanza (скачивание из релиза, sha256, распаковка, проверка правила 52/52)
python scripts\unpack_models.py --release models-v1 --check

# 4. прописать сервер в клиенте (LM Studio и др.)
python scripts\install_mcp.py

# 5. приёмка
python scripts\doctor.py
python правило\smoke_test.py --full
```

Порядок 2 → 3 важен: `--check` у распаковки прогоняет валидатор, а для него нужны зависимости.
Если зависимостей нет, распаковка всё равно работает (`--check` можно добавить позже).

**Linux/macOS:** шаг 2 вручную —
`python3.11 -m venv .venv && .venv/bin/python -m pip install -r requirements.txt`
и скопировать `правило/git-hooks/pre-commit` в `.git/hooks/pre-commit` (с LF).
Остальные шаги те же.

**Другой каталог для моделей** (например, на быстром диске):

```powershell
python scripts\unpack_models.py --release models-v1 --dest D:\stanza-models --check
# скрипт напечатает строку для окружения:
#   STANZA_RESOURCES_DIR=D:\stanza-models
```

Эту переменную нужно добавить в `env` сервера `stanza-german` в `mcp.json`
(или выполнить `python scripts\install_mcp.py` заново — он подставит текущий путь кэша)
и в окружение, где запускаются `doctor.py` / `smoke_test.py --full`.

## Обновить существующую копию

```powershell
cd C:\KI_WORK
git pull                                   # правило/код/данные
python scripts\doctor.py                   # если появились FAIL — см. ниже
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1   # только если менялись requirements*
```

Модели обновляются только при смене версии Stanza: тогда публикуется новый ассет
(см. «Обслуживание») и выполняется `unpack_models.py --release <новый тег> --force`.

## Приёмка после переноса

| Проверка | Команда | Ожидаемый результат |
|---|---|---|
| окружение | `python scripts\doctor.py` | `FAIL 0`, `ИТОГ: машина готова` |
| целостность | `python правило\smoke_test.py` | `OK 11, FAIL 0` (0.03 с, без Stanza) |
| живой прогон | `python правило\smoke_test.py --full` | `OK 14, FAIL 0`; F1 0.777 (52) и 0.686 (51) |
| правило на разметке | `python правило\validator.py --set bench/sets/corpus52.jsonl` | `compliant 52` |
| известные расхождения | `... --set bench/sets/heldout_51.jsonl` | `compliant 45` (6 нарушений — список в `ПРАВИЛО.md` §5) |
| MCP-сервер | в чате: `pipeline_info()` | `rule_registered: true`, `notes: []`, `rule_root` = `<ваш путь>\правило` |
| судья | в чате: `rule_self_test()` | `gate_passed: true`, `failed_ids: []` |
| нарезка | в чате: `segment_german("Ich habe bei der Firma gearbeitet.")` | 2 блока, `blocks_total: 2` |

## Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| `doctor`: `FAIL stanza_de — нет моделей de` | не выполнен шаг 3 | `python scripts\unpack_models.py --release models-v1 --check` |
| `gh: Not Found` при скачивании | `gh` не авторизован / нет доступа к приватному репозиторию | `gh auth login`; либо скачать zip вручную из Releases и `--zip` |
| `RuntimeError: Stanza pipeline не удалось загрузить` | модели лежат в нестандартном каталоге, `STANZA_RESOURCES_DIR` не задан | задать переменную (её печатает `unpack_models.py`) |
| `pipeline_info().notes`: «правило не подключено» | рядом с `server.py` нет папки `правило`, или `RULE_ROOT` в `mcp.json` указывает в никуда | `python scripts\install_mcp.py` (перезапишет `env.RULE_ROOT`) |
| В конфиге клиента остались старые абсолютные пути | конфиг правился руками до скриптов | `python scripts\install_mcp.py` — перезапишет запись `stanza-german`, остальные серверы сохранит |
| `setup.ps1` блокируется политикой | ExecutionPolicy | запускать через `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1` |
| Кракозябры в выводе скриптов | консоль не в UTF-8 | скрипты печатают в UTF-8: `chcp 65001` или Windows Terminal |
| `pip`: `Connection aborted 10054` | обрыв сети к pypi | повторить `setup.ps1` (pip докачивает из кэша) |
| `sha256 не совпал` | архив скачался битым | удалить zip и повторить `unpack_models.py` |
| Хук не срабатывает | `pre-commit` с CRLF | `setup.ps1` переустанавливает его с LF |

## Обслуживание: новый архив моделей

Нужен при смене версии Stanza (сейчас `STANZA_VERSION = 1.15.0` в `scripts/_paths.py`).

```powershell
# 1. скачать модели новой версии в кэш (нужна сеть, один раз)
python -m stanza.download de

# 2. собрать архив и сумму (--minimal = только то, что нужно коду: ~315 МБ)
python scripts\pack_models.py --minimal

# 3. опубликовать новый тег
gh release create models-v2 stanza-models-de-1.15.0.zip stanza-models-de-1.15.0.zip.sha256 `
   -t "Stanza de models <версия>" -n "комментарий"
```

`pack_models.py` без флагов собирает полный набор процессоров (853 МБ), `--keep-zip` —
весь кэш как есть (1.6 ГБ). Эталонная `stanza-models-de-1.15.0.zip.sha256` хранится в git,
поэтому совпадение архива проверяется даже без файла суммы рядом.

## Справочник по скриптам

| Скрипт | Назначение | Ключевые флаги |
|---|---|---|
| `scripts/doctor.py` | preflight: Python, пины, модели, правило, наборы, RULE_ROOT, git | `--json`, `--soft-models` |
| `scripts/setup.ps1` | venv + зависимости + LF-хук + doctor | `-UseLock`, `-SkipDeps`, `-DryRun`, `-VenvDir` |
| `scripts/unpack_models.py` | скачать/распаковать модели, проверить sha256 и правило | `--release`, `--zip`, `--dest`, `--check`, `--force` |
| `scripts/pack_models.py` | собрать архив моделей для нового релиза | `--minimal`, `--keep-zip`, `--out` |
| `scripts/install_mcp.py` | прописать `stanza-german` в `mcp.json` клиента | `--dry-run`, `--print`, `--config` |
