# ПЛАН: проверка обновлений зависимостей

Один вопрос и ничего больше: **вышли ли новые версии**. Никакого анализа рисков, verdict-ов,
гейтов и отдельных отчётов. Ответ агент получает в `pipeline_info()`.

Уже есть: `scripts/pins.py --latest` (PyPI JSON API, кэш `bench/cache/pypi_index.json`, TTL 6 ч,
`--json`) и еженедельный job `pins`. Не хватает только двух вещей: файл-снимок и вывод в сервер.

## Шаг 1 — `pins.py`: снимок файла (~15 строк)

Флаг `--write <файл>` (по умолчанию `bench/results/deps.json`):

```json
{
  "as_of": "2026-11-17T15:00:00Z",
  "python": "3.15",
  "packages": { "stanza": {"current": "1.15.0", "latest": "1.15.1"},
                "torch":  {"current": "2.15.0", "latest": "2.15.0"} },
  "models":   { "stanza": "1.15.0", "pack_ok": true }
}
```

- `latest` — из существующего `pins.py:latest_version()`, `current` — из `requirements.txt` (пин).
- `models.pack_ok` — два факта: версия stanza из пакета и есть ли в кэше `de/depparse`. Без анализа.
- Без сети и без кэша PyPI — файл не пишется, скрипт говорит «данных нет» (код 2 у `pins.py` уже есть).

Критерий: `python scripts/pins.py --latest --write` даёт файл со всеми пятью пакетами и `as_of`.

## Шаг 2 — `server.py`: вывод в `pipeline_info()` (~15 строк)

- Читает `bench/results/deps.json` (путь от корня проекта; сеть не трогает).
- Новое поле `updates` в ответе `pipeline_info()`:
  `{"as_of": "…", "stale_days": 3, "outdated": [{"name": "stanza", "current": "1.15.0", "latest": "1.15.1"}], "models_ok": true}`
- Файла нет → `"updates": {"available": false}`; сервер не падает, остальные поля не меняются.

Критерий: в чате `pipeline_info().updates.outdated` показывает stanza 1.15.0 → 1.15.1 и дату снимка.

## Шаг 3 — CI (~8 строк yaml)

`pins.yml`: `python scripts/pins.py --latest --write bench/results/deps.json` + коммит этого файла
(`permissions: contents: write`). Раз в неделю, одним коммитом. Артефактов, сводок и авто-PR нет.

## Шаг 4 — тексты (~10 строк)

`УСТАНОВКА.md` §1.8: «обновления смотрит `pins.py --latest`; агент видит их в `pipeline_info().updates`
(свежесть — по `as_of`)». §2 «Агенту»: «обновления брать только из `updates`, судить по `as_of`;
сам ничего не обновлять — правка пина = приёмка §1.4».

## Чего в плане нет

`deps.py`, гейтов `--check`, колонок `risk`/`verdict`, новых MCP-инструментов, правок `doctor.py` и
`smoke_test.py`, CI-артефактов, автоматических обновлений.

## Объём и риски

~40 строк Python + ~8 yaml + ~10 строк текстов. Риски: PyPI недоступен → файл не обновляется,
`stale_days` растёт и агент видит «данные устарели»; устаревший снимок в git → ровно на это и есть
`as_of`/`stale_days`.
