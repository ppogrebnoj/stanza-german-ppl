# План V3: от стенда к программе

**Принцип из ТЗ:** в руках — правило-инструкция + работающий валидатор (ваше Q8).
**Реализация:** алгоритм оценивает границы → DP выбирает нарезку → валидатор проверяет запреты.

---

## 0. Что уже готово (не требует работы)

- Стенд `bench/` с 13 алгоритмами и метриками — работает.
- Данные: `corpus52_v2` (52), `heldout_mini` (12) — в машинном виде.
- Победитель: **S4** (гибрид) и **S1** (дерево зависимостей) — F1 0.74 на 52, 0.78–0.80 на 12 heldout.
- Запреты и штрафы — спецификация с замерами (`03_ЗАПРЕТЫ_И_ШТРАФЫ.md`).
- Параметры-победители — `bench/results/best_params_v3.json`.

## 1. Что делаем (по шагам)

| Этап | Что | Время | Готово, когда |
|---|---|---|---|
| **1** | `reference/segment.py`: S1 (или S4) + запреты + штрафы + DP(mean) + слоги | 1 день | на 12 heldout F1 ≥ 0.75 |
| **2** | `config.json → segment`: все числа (ideal 3, cap 6, w 0.3, веса штрафов) | 0.5 дня | параметры читаются из конфига, код их не знает |
| **3** | Валидатор `check()` V3: B1–B6 + длина + слоги + пунктуация + «цена штрафов» | 1 день | ваша разметка 52 = compliant 52/52 |
| **4** | CLI `--segment "предложение"` и `--segment-file page.txt` | 0.5 дня | «вставил страницу — получил блоки» |
| **5** | Делитель предложений SoMaJo перед Stanza (страница целиком, Q12) | 0.5 дня | на 19 «трудных» кейсах 19/19 |
| **6** | Нормализация «битого» текста (Q13): кавычки, дефисы, неразрывные пробелы | 0.5 дня | `hard_inputs.md` проходит целиком |
| **7** | MCP-инструмент `segment_german` (рядом с `check_segmentation`) | 0.5 дня | вызов из MCP возвращает блоки + объяснение |
| **8** | Документ-правило `RULE_V3.md`: 1 страница для программиста | 0.5 дня | программист может реализовать по нему с нуля |
| **9** | Финальная проверка на 150 (когда разметите) | — | цифры на незнакомом материале |

Итого: **~5 рабочих дней** (этапы 1–8), этап 9 ждёт вашу разметку.

## 2. Что будет в `config.json` (новый раздел)

```json
"segment": {
  "algorithm": "S1",
  "objective": "mean",
  "min_lex": 2,
  "ideal_lex": 3.0,
  "max_lex": 6,
  "w_len": 0.3,
  "syllables": { "max_words": 3, "from": 7 },
  "bans": {
    "after_upos": ["ADP", "DET", "CCONJ", "SCONJ", "PART"],
    "before_upos": ["PUNCT"],
    "inside_hyphen_word": true,
    "after_open_quote": true,
    "after_adp": true
  },
  "penalties": { "np_inner": 0.35, "before_aux": 0.25, "subj_verb": 0.25 }
}
```

Ни одного немецкого слова в коде: все списки — данные.

## 3. Как проверяем качество (гейты)

| Гейт | Условие |
|---|---|
| G1 | на 52 (настройка) F1 ≥ 0.72 |
| G2 | на 12 heldout F1 ≥ 0.75 (сейчас 0.78–0.80) |
| G3 | 0 блоков вне 2–6 слов; 0 резов после служебного слова; 0 резов перед пунктуацией |
| G4 | ваша разметка 52 проходит новый валидатор как `compliant` (52/52) |
| G5 | «страница целиком» (5 предложений) обрабатывается < 2 с, границы предложений верные |
| G6 | повторный прогон даёт тот же результат (детерминизм, sha256) |

## 4. Что НЕ делаем в V3

| Не делаем | Почему |
|---|---|
| Новые классы правил C15+ | F1 упал бы к 0.36 (замер S5) |
| Обучение своей модели (Путь 2) | нет 150 разметки; вернёмся после этапа 9 |
| LLM-генерация (Путь 3) | на этой задаче хуже (по литературе F1 5–18, и портит текст) |
| Переписывание `rule.py` с нуля | он остаётся валидатором, меняется только набор проверок |

## 5. Риски

| Риск | Что делаю |
|---|---|
| 12 heldout — маленькая выборка, «0.80» может быть случайным | финальное слово за 150; на 52 и на 12 победитель один и тот же (S4/S1) — это хороший знак |
| Параметры переобучены на 52 | все они — 4 числа; при появлении 138 новых предложений перепроверю сеткой |
| Constituency-модель Stanza иногда не сходится с токенами (43/150) | S1 не зависит от constituency (только зависимости); S4 — гибрид, при сбое падает на S1 |
| SoMaJo GPL-3.0 | личное использование — ограничений нет; при распространении заменим на 5 правил поверх Stanza |
