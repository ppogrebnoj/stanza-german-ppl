# ПРОТОКОЛ — цикл доработки правила (немецкая сегментация по Stanza)

## Файлы цикла
| Файл | Назначение |
|---|---|
| `RULE.md` | Текущее правило (единый файл, версия в шапке). |
| `reference/config.json` | Машинальная версия правила: условия C1..C5/NO-CUT/P1-P2, параметры min/pref/cap; единый файл без номера. Дельта LLM = патч конфига. |
| `PROMPT.md` | Промт для LLM (вход, шаги, секции вывода). |
| `CORPUS/verified.jsonl` | Хранимый корпус verified-разбиений человека (ground truth). |
| `GAPS/registry.md` | Реестр GAP-типов через Stanza-признаки. |
| `LOG/iterations.md` | Лог итераций + история правил. |
| `reference/rule.py` | Референс-интерпретатор + self_test(). |

## Гейт приёма ground truth
Разбивку человека принимаем как **verified** только если: 1) детерминированность (P1/P2, min/cap); 2) только Stanza-поля (deprel/xpos/lemma/is_mwt); 3) ноль регресса по всем ранее verified-кейсам; конфликты — явное решение в GAPS.

## Итерация
Человек — разбивка → **rule.py --check** → match? diagnosis?
- match=true (soft) + self_test() 100% → человек подтверждает → CORPUS verified, GAPS resolved, LOG, git commit + tag v{n+1}.
- match=false → LLM готовит минимальную дельту по facts из diagnosis → патч config.json → repeat (max 5 попыток) → report человеку.
- git commit + tag — только при успехе; до этого config = черновик.

## Версионирование
Правило — единый RULE.md (версия в шапке); история — git-теги + LOG/iterations. Конфиг — единый config.json (внутренняя версия = версия правила). PROMPT.md обновляется только вместе с правилом.

## Счётчик N
N = номер последней зафиксированной версии правила (таблица в LOG/iterations.md); текущая базовая — v3, N=3.

## Критерии выхода в ТЗ
Выход допустим только когда **все** условия выполнены: 1) >=20 verified-кейсов в CORPUS/verified.jsonl (accepted=true); 2) GAP-реестр: все resolved + все seam-классы C1–Cn = verified («resolved» ≠ «verified»: необходимое, а не достаточное условие); 3) последние 3 итерации — только уточнения: без новых C-классов и без изменения NO-CUT/P1-P2; 4) регресс 100% — все verified-кейсы воспроизводятся текущей версией без конфликтов.
