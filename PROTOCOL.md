# ПРОТОКОЛ — цикл доработки правила RULE v5 (немецкая сегментация по Stanza)

Цель цикла: человек даёт разбивку предложения, LLM корректирует правило по промту **PROMPT.md**. После достаточного числа итераций правило становится техническим заданием для программирования. Сейчас работаем только над правилом и промтом.

## Роли
- **Человек** — ground truth: даёт разбивку предложения (блоки). Человек = эталон; правило меняется, а не эталон.
- **LLM** — инженер формального правила сегментации немецкого текста по Stanza 1.15.0. Единственный источник — поля Stanza: `id, text, lemma, upos, xpos, feats, head, deprel, is_mwt` + дерево constituency (NP/PP/VP/CNP). Запрещены семантические и оценочные рассуждения; паузы не используются.

## Файлы цикла
| Файл | Назначение |
|---|---|
| `RULE v{N}.md` | Текущая версия правила (отдельный файл на версию в корне). Базовая — RULE v5.md.
| `PROMPT.md` | Промт для LLM (v5.1).
| `CORPUS/verified.jsonl` | Хранимый корпус verified-разбиений человека (ground truth); по 1 кейсу на строку.
| `GAPS/registry.md` | Реестр GAP-типов, сформулированных только через Stanza-признаки.
| `LOG/iterations.md` | Лог итераций (счётчик N).
| `CHANGELOG.md` | Единый changelog по всем версиям правила.

## Формат входа (человек → LLM)
Строго:
```text
Предложение: <текст>
Блоки:
1) <блок 1>
2) <блок 2>
...
Комментарий: <опционально>
```
- Блок — текст непрерывного отрезка предложения (включая знаки, если они внутри блока).
- Нумерация `1)` … по порядку слева направо.

## Правило приёма ground truth (вердикт → приём)
Разбивку человека принимаем как **verified** только если:
1. **Детерминированность** — разбивка воспроизводится правилом детерминированным способом (seam-множество, P1/P2, min/cap).
2. **Только Stanza-поля** — обоснование резов/объединений выражено только через Stanza-признаки (`deprel/xpos/lemma/is_mwt`), без семантики и пауз.
3. **Ноль регресса** — новая версия правила воспроизводит все ранее verified-кейсы `CORPUS/verified.jsonl`; конфликты разрешаются явным решением (запись в `GAPS/registry.md`).

## Итерация (LLM → человек)
LLM выдаёт 8 секций + машиночитаемый JSON-блок итога (см. PROMPT.md):
1) Таблица Stanza; 2) Seam-разбор; 3) Вердикт; 4) Delta; 5) RULE v{n+1}; 6) Регресс; 7) GAP-типы; 8) Вопросы.
После вердикта человек: принимает / корректирует разбивку → LLM пишет дельту, обновляет `RULE v{n+1}`, `CORPUS/verified.jsonl`, `GAPS/registry.md`, `LOG/iterations.md`, `CHANGELOG.md`.

## Версионирование
- Правило — отдельный файл на версию в корне: **RULE v6.md, RULE v7…** (v5 = базовая).
- PROMPT.md — отдельная версия (v5.1), обновляется только вместе с правилом.

## Критерии выхода в ТЗ для программирования
Выход допустим только когда **все** условия выполнены:
1. **>=20 verified-кейсов** в `CORPUS/verified.jsonl` (accepted=true).
2. **Реестр GAP пуст / все решены** — `GAPS/registry.md`: статус каждого gap = resolved.
3. **Последние 3 итерации — только уточнения**: без новых seam-классов (C5… не добавляются) и без изменения NO-CUT/P1/P2.
4. **Регресс 100%** — все verified-кейсы воспроизводятся текущей версией правила без конфликтов.

## Счётчик N
N = номер последней зафиксированной версии правила (в `LOG/iterations.md` и `CHANGELOG.md`). Текущая базовая версия — **v5**.
